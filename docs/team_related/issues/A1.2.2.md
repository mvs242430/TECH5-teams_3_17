# Issue A1.2.2 — Projects: form edge cases (`max_capacity >= 1`, empty ID state retention) & full-layer schema test

`team-a` · A1 · Week 1–2 · S · Needs: A1.2, A1.2.1

**What and why:** Two edge cases exist in project creation/editing, and we need full-layer test coverage across all related SQLite tables and rendered HTML views:
1. The SQLite `projects` table enforces `CHECK(max_capacity >= 1)`, but `_parse_and_validate_project_form` only checks `if min_capacity < 0 or max_capacity < 0:`. Submitting `min_capacity=0, max_capacity=0` bypasses form validation and triggers a raw `sqlite3.IntegrityError` instead of a friendly validation message.
2. In `create_project`, when `project_id` is empty (`""`), `project_form.html` is re-rendered with `form_data` but without `req_levels` and `req_mands`, wiping out all skill levels and mandatory checkboxes the user had configured.
3. Existing tests check `ProjectRepository.get_by_id`, but do not verify: (a) rendered `/projects` catalog badges (`Must-have` vs. `Nice-to-have` and seat capacities), (b) edit form `checked` attribute pre-filling on mandatory checkboxes, or (c) raw SQLite rows and `ON DELETE CASCADE` across `projects`, `project_requirements`, `preferences`, `fixed_assignments`, and `assignments`.

**Files:** `app/visualization/routes.py` (`_parse_and_validate_project_form`, `create_project`), `app/visualization/templates/project_form.html`, `app/visualization/templates/projects.html`, `tests/test_visualization_component.py` (add new test `test_projects_edge_cases_and_full_layers`; do not modify existing tests), `docs/team_related/issues/A1.2.1.md`, `docs/team_related/issues/A1.2.2.md`.

**What to build:**
- In `_parse_and_validate_project_form` (`app/visualization/routes.py`):
  - Validate that `max_capacity >= 1` (e.g., if `max_capacity < 1`, return a friendly error message such as `"Maximum capacity must be at least 1."` before hitting the database).
- In `create_project` (`app/visualization/routes.py`):
  - When `not project_id`, also parse and pass `req_levels` and `req_mands` into `flask.render_template("project_form.html", ...)` so the user's selected skill levels and mandatory checkboxes are retained when re-rendering the form.
- In `tests/test_visualization_component.py`, add a new test `test_projects_edge_cases_and_full_layers` (without changing any existing tests) that verifies:
  1. Submitting `min_capacity=0, max_capacity=0` flashes a friendly validation error (`"Maximum capacity must be at least 1."`) rather than a raw SQLite constraint error.
  2. Submitting an empty `id` on `POST /projects/new` retains entered `req_level_<skillid>` and `req_mand_<skillid>` values in the re-rendered form HTML.
  3. Creating a project with both a mandatory skill (`py`, level 4) and a nice-to-have skill (`sql`, level 2) stores the exact rows in `projects` and `project_requirements`, and renders `1 &ndash; 3 seats`, `py: L4 (Must-have)`, and `sql: L2 (Nice-to-have)` on `GET /projects`.
  4. `GET /projects/<id>/edit` pre-fills `checked` on the mandatory skill checkbox and does not mark the nice-to-have skill checkbox as `checked`.
  5. Editing the project to set `req_level_sql=0` removes `sql` from `project_requirements` in the database and from `GET /projects`.
  6. Deleting the project cascades across `project_requirements`, `preferences`, and `fixed_assignments` in SQLite, leaving 0 orphaned rows.
