# Issue A1.2.1 — Projects: mandatory skill requires level 1–5 & level range validation

`team-a` · A1 · Week 1–2 · S · Needs: A1.2

**What and why:** In the project creation/edit form (`project_form.html`), every skill's required minimum level defaults to `0` (`0 = None`). Currently, if an Admin ticks the "Hard / Mandatory Requirement" checkbox (`req_mand_<skillid>`) for a skill in the browser without changing `req_level_<skillid>` from `0`, `_parse_and_validate_project_form` silently drops the skill requirement (`if 1 <= req_levels[skill.id] <= 5`) and saves the project with no requirement and no warning. Additionally, skill levels outside `0–5` are silently ignored instead of showing an error.

**Files:** `app/visualization/routes.py` (`_parse_and_validate_project_form`), `app/visualization/templates/project_form.html`, `tests/test_visualization_component.py` (add new test `test_project_mandatory_skill_requires_level`; do not modify existing tests), `docs/team_related/issues/A1.2.1.md`, `docs/team_related/issues/A1.2.2.md`.

**What to build:**
- In `_parse_and_validate_project_form` in `app/visualization/routes.py`:
  1. If `req_mand_<skillid>` is ticked (`True`) while `req_level_<skillid>` is `0` (or empty), reject the submission and return a clear red flash error message (e.g., `"Cannot mark skill '<skill.name>' as mandatory without selecting a required minimum level (1-5)."`). Do not save the project; re-render `project_form.html` with `form_data`, `req_levels`, and `req_mands` preserved so the user does not lose their input.
  2. If `req_level_<skillid>` is not a valid integer between `0` and `5` (e.g., negative or `> 5`, or non-numeric string), reject the submission with a clear red flash error message (e.g., `"Skill requirement level for '<skill.name>' must be between 0 and 5."`) and re-render the form preserving user input.
- Add a new test function `test_project_mandatory_skill_requires_level` in `tests/test_visualization_component.py` (leave existing `test_projects_crud_workflow` unchanged) that verifies:
  1. Submitting `POST /projects/new` (and `POST /projects/<id>/edit`) with `req_mand_<skillid>=1` and `req_level_<skillid>=0` (or omitted) returns a danger flash message and does not save/update the project in the database.
  2. Submitting a skill level outside `0–5` (e.g., `req_level_<skillid>=6` or `-1`) returns a danger flash message and does not save.

**How to solve with the AI:**
1. Ask the AI to inspect `_parse_and_validate_project_form` in `app/visualization/routes.py`.
2. Add the validation checks for mandatory skills with level 0 and out-of-range skill levels (`< 0` or `> 5`).
3. Write the new test `test_project_mandatory_skill_requires_level` in `tests/test_visualization_component.py` without editing any existing test functions.
4. Run `pytest` and the `qa-tester` subagent before committing.

**Prompt:** "Read `docs/team_related/issues/A1.2.1.md` and `_parse_and_validate_project_form` in `app/visualization/routes.py`. Implement the validation rules so that ticking a mandatory skill (`req_mand_<skillid>`) when `req_level_<skillid>` is 0 (or empty), or providing a skill level outside 0–5, flashes a danger error message, preserves `form_data`, `req_levels`, and `req_mands`, and does not save to the database. Add a new test `test_project_mandatory_skill_requires_level` in `tests/test_visualization_component.py` without modifying existing tests. Run pytest."

**Done when:** ☐ Ticking Mandatory with level 0 flashes a red error message and does not silently drop the skill ☐ Skill levels outside 0–5 flash a red error message ☐ `test_project_mandatory_skill_requires_level` passes ☐ All existing tests remain untouched and passing.
