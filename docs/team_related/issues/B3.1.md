# Issue B3.1 — The engine "boss": run everything

`team-b` · B3 · Week 1–2 · L · Needs: 0.5 (placeholder first), B2.2 later

**What and why:** `AssignmentEngine.execute_run` is what the web app calls. It validates, solves up to K alternatives, calculates indicators, saves results, and returns a run. Right now it raises "not implemented" and the app uses the fake engine.

**Files:** `app/engine/solvers.py`.

**Steps:**
1. Register the strategies (`PREFERENCE`, `SKILL_FIT`, `BALANCED`) in `__init__`.
2. Call `validate_inputs`; if input invalid → run with status `INVALID_INPUT` and the errors; if proven infeasible → status `INFEASIBLE` with reasons.
3. Otherwise get up to `max_alternatives` solutions (strategy plan from B-0), compute indicators with `metrics.compute_solution_indicators`, create `models.Solution` objects numbered from 1.
4. Save with `self.run_repo.save_run(run)` and return it. Make sure students/projects exist in the database before saving (see `docs/internal_component_contract.md` §5).

**Week 1 trick (so B3 isn't waiting):** write a trivial placeholder strategy (give each student their first free choice) so the whole pipeline runs. Swap in B2's strategies in Week 2.

**Hint:** `MockAssignmentEngine.execute_run` in `app/contract/mocks.py` is a working example of the shape. Copy the structure, not its fake logic.

**Prompt:** "Read app/contract/contract.py, app/contract/mocks.py (MockAssignmentEngine.execute_run), app/domain/validation.py and app/engine/solvers.py. Implement `AssignmentEngine.execute_run` following the 4 steps in the issue. Status values are the strings COMPLETED, INFEASIBLE, INVALID_INPUT, WARNING, FAILED. Never let an infeasible problem raise an exception. Edit only app/engine/solvers.py."
