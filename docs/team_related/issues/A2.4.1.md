# Issue A2.4.1 — Role UI, Scenarios Access & Pseudonymized Student Allocations

`team-a` · A2 · Week 3 · S · Needs: A2.4

**What and why:** Follow-up role-based UI, route, and transparency cleanup after live walkthrough of the `COORDINATOR` and `STUDENT` views:
1. The navbar displays `Role: Programme Coordinator (Runs & Analysis)` / `Role: Student Viewer (Read Only)` next to `Return to Administrator`, crowding the header; it should display compact labels (`Role: Coordinator` and `Role: Student`) on the navbar while preserving full `ALL_ROLES` descriptions for role-switch flash messages.
2. On `/skills`, `COORDINATOR` and `STUDENT` see an unusable `+ Add New Skill` card containing only a warning banner; the entire `+ Add New Skill` card should be removed for non-Admin roles so the catalog table renders cleanly at full width.
3. Neither `COORDINATOR` nor `STUDENT` may load scenarios (cohort replacement is `ADMIN`-only per `docs/architecture.md` §6). The `/scenarios` page, its navbar link, and the Dashboard `Quick Benchmark Scenarios` card should be removed/refused for `COORDINATOR` and `STUDENT`.
4. On `/solutions/<id>` (**Student-to-Project Allocations**) and `/compare` (**Detailed Allocation Shifts**), `STUDENT` should see pseudonymized `student_id` rows (`S01`, `S02`, ...) with **no** `display_name`, allowing students to verify allocations by ID without exposing classmates' names.
5. On `/`, the entire **Run Assignment Optimization (Service A)** card should be removed for `STUDENT` (instead of rendering a disabled card with a stretched permission warning), and Dashboard KPI card links should say `View Projects →` / `View Students →` (omitting `& Edit`) whenever `can_edit` is `False`.

**Files:** `app/visualization/auth.py`, `app/visualization/routes.py`, `app/visualization/templates/base.html`, `app/visualization/templates/dashboard.html`, `app/visualization/templates/skills.html`, `app/visualization/templates/solution_detail.html`, `app/visualization/templates/compare.html`, `docs/architecture.md`, `tests/test_visualization_component.py` (new A2.4.1 tests plus authorized updates to the A2.4 `/scenarios` and pseudonymized-ID assertions; zero starter tests touched), `docs/team_related/issues/A2.4.1.md`, `docs/team_related/issues_solutions/A2.4.1_solution.md`.

**What to build:**
- Add `UserRole.NAV_LABELS` (`ADMIN: "Administrator"`, `COORDINATOR: "Coordinator"`, `STUDENT: "Student"`) in `app/visualization/auth.py`, expose `nav_role_labels` via `inject_template_globals()` in `app/visualization/routes.py`, and render `nav_role_labels` in `app/visualization/templates/base.html` so the navbar displays `Role: Coordinator` and `Role: Student` while `UserRole.ALL_ROLES` preserves full flash descriptions for baseline tests.
- Guard `GET /scenarios` (`scenarios_page` in `app/visualization/routes.py`) with `auth.can_edit_cohort_data()`, flashing `"Permission denied for current role."` and redirecting `COORDINATOR` and `STUDENT` to `/`.
- Gate the `Scenarios` navbar item in `base.html`, the `Quick Benchmark Scenarios` card (`can_edit`), the entire `Run Assignment Optimization (Service A)` section (`can_optimize`), and the `& Edit` wording on Dashboard KPI links (`can_edit`) in `dashboard.html`.
- Gate the `+ Add New Skill` card, empty-catalog form hint, and `grid-2` wrapper in `skills.html` behind `can_edit`.
- In `view_solution()` and `compare_solutions()` (`app/visualization/routes.py`), omit student `display_name` lookups when `auth.can_view_student_records()` is `False`, and update `solution_detail.html` and `compare.html` to render `student_id` (`<th>Student ID</th>`) with zero student names for `STUDENT` while preserving full `display_name` + `ID` for `ADMIN` and `COORDINATOR`.
- Update `docs/architecture.md` §6.1 Role × Action Table and `tests/test_visualization_component.py`, and add dedicated tests for all four A2.4.1 behaviors.
