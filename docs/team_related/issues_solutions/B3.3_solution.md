# Issue B3.3 Solution — Run Diagnostics & Infeasibility Explanations

## 1. Architectural Pattern Applied & Rationale
- **Pattern:** **Structured Diagnostic Telemetry via Domain DTO (`AssignmentRun.diagnostics`)**.
- **Rationale:** When an optimization run fails or proves mathematically infeasible, coordinators need actionable, human-readable explanations rather than an opaque solver error or crash. Storing structured diagnostic metadata in `run.diagnostics` allows Component A (`run_detail.html`) to display exact bottleneck reasons, warnings, solve times, and problem dimensions without coupling the UI to Pyomo internals.

## 2. High-Level Logic & Data Flow Walkthrough
1. **Pre-Solver Infeasibility (`status = "INFEASIBLE"`):**
   - Populates `run.diagnostics` with `solver_status`, `strategy`, `solve_time_seconds`, `variables`, `constraints`, `alternatives_found: 0`, `distinct_alternatives: 0`, `reasons` (from `val_outcome.infeasibility_reasons`), `errors`, `warnings`, `notes`, and a summary `message`.
2. **Pre-Solver Validation Error (`status = "INVALID_INPUT"`):**
   - Populates `run.diagnostics` with `reasons` and `errors` from `val_outcome.errors`, plus `warnings`, `solve_time_seconds`, `variables`, and `constraints`.
3. **Solver-Detected Infeasibility (`status = "INFEASIBLE"` when `len(solutions) == 0`):**
   - If pre-validation passed but the MILP solver proved the combined constraints infeasible, populates `run.diagnostics["reasons"]` with actionable remediation hints (relaxing mandatory skills, reducing minimum capacities, or removing conflicting fixed locks).
4. **Completed Runs (`status = "COMPLETED"`):**
   - Records `solve_time_seconds`, `variables`, `constraints`, `solution_count`, `alternatives_found`, `distinct_alternatives`, `warnings`, `notes`, and `message`.
5. **Template Alignment (`app/visualization/templates/run_detail.html`):**
   - Verified that `run_detail.html` reads `run.diagnostics.get('message')`, `run.diagnostics.get('reasons')`, `run.diagnostics.get('errors')`, `run.diagnostics.get('warnings')`, and `run.diagnostics.get('notes')`.

## 3. Summary of Files Changed
- `app/engine/solvers.py`: Populated `run.diagnostics` across all execution paths (`INFEASIBLE`, `INVALID_INPUT`, and `COMPLETED`) in `AssignmentEngine.execute_run`.

## 5. Pedagogical Checkpoint — Check Your Understanding
1. **Which keys in `run.diagnostics` does `run_detail.html` render in the UI?**
   - `message` (bold summary header), `reasons` (red bulleted list of infeasibility causes), `errors` (red bulleted list of validation errors), `warnings` (amber notices), and `notes` (administrative notes).
2. **Why can a cohort pass `validate_inputs` and still be found infeasible by the MILP solver?**
   - Pre-validation checks aggregate capacity and individual project bounds, whereas combinatorial conflicts (for example, two projects each requiring minimum capacity 1 of a mandatory skill that only one student in the cohort possesses) are only proven infeasible when solving the simultaneous MILP constraints.
