# Issue B3.4 Solution — Activating the 7 Solver Edge-Case Tests

## 1. Architectural Pattern Applied & Rationale
- **Pattern:** **Boundary & Edge-Case Verification across Domain, Strategy, and Engine Layers**.
- **Rationale:** Section 13 of the TECH5 specification defines 15 edge cases covering incomplete preferences, tied rankings, missing skills, zero project requirements, capacity deficits, contradictory locks, impossible mandatory skills, single-solution cohorts, and duplicate avoidance via integer no-good cuts. With `metrics.py`, `strategies.py`, and `solvers.py` (`execute_run`) implemented, removing the `@pytest.mark.xfail` decorators from Edge Cases 1, 2, 3, 4, 13, 14, and 15 verifies that all 15 edge cases pass end-to-end.

## 2. High-Level Logic & Data Flow Walkthrough
1. **Case 1 (`test_edge_case_1_incomplete_preferences`):** Unranked projects receive fallback utility (`0.0` in `PreferenceOrientedSolver` and `1.0 / (M + 1)` in `BalancedTradeoffSolver`), allowing students with partial preference lists to be assigned cleanly.
2. **Case 2 (`test_edge_case_2_tied_preferences_across_students`):** The MILP capacity constraint ($\sum_s x_{s,p} \le u_p$) forces the solver to break ties while respecting project capacity limits.
3. **Case 3 (`test_edge_case_3_zero_skills_student`):** `metrics.calculate_assignment_skill_fit` returns `0.0` when a student has `{}` skills and the project has soft skill requirements.
4. **Case 4 (`test_edge_case_4_zero_requirements_project`):** `metrics.calculate_assignment_skill_fit` returns `1.0` (neutral full fit) when `project.requirements` is empty.
5. **Case 13 (`test_edge_case_13_no_feasible_solution`):** `AssignmentEngine.execute_run` detects `not val_outcome.is_feasible` (1 student < min capacity 2) and returns `run.status == "INFEASIBLE"` with `len(run.solutions) == 0`.
6. **Case 14 (`test_edge_case_14_single_feasible_solution`):** After finding the sole valid allocation on iteration 1, the no-good cut excludes it on iteration 2; the solver reports `INFEASIBLE`, the loop stops cleanly with `len(run.solutions) == 1`, and `run.diagnostics["distinct_alternatives"] == 1`.
7. **Case 15 (`test_edge_case_15_duplicate_avoidance_no_good_cuts`):** With 2 students and 2 capacity-1 projects (`max_alternatives=3`), integer no-good cuts find both valid permutations and terminate cleanly with 2 strictly distinct solutions.

## 3. Summary of Files Changed

- `app/engine/solvers.py`: Included `"distinct_alternatives": len(solutions)` in `run.diagnostics` and handled uncatalogued skill synchronization.

## 5. Pedagogical Checkpoint — Check Your Understanding
1. **In Edge Case 14 (`max_alternatives=3` on a 1-student, 1-project cohort), why does `execute_run` return 1 solution with status `COMPLETED` instead of failing when alternatives 2 and 3 are infeasible?**
   - Because at least one feasible solution was found (`len(solutions) == 1`). When subsequent iterations become infeasible due to the no-good cuts exhausting the entire feasible solution space, the loop breaks and returns all distinct feasible solutions discovered (`distinct_alternatives = 1`).
