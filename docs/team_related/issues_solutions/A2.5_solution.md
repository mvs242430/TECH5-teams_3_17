## 5. Pedagogical Checkpoint ("Check Your Understanding")

1. **Why does Component B (`app/engine`) not import Flask, Jinja2, or HTTP session objects?**
   - *Defense:* Component B is designed as a pure, headless decision engine. Keeping it free of presentation and web framework dependencies means it can be executed, benchmarked, and tested directly in headless Python scripts, CLI tools, or batch runners without requiring a web server or request context.
2. **What is the difference between `RunRequest` and `AssignmentRun`?**
   - *Defense:* `RunRequest` is an input Data Transfer Object (DTO) containing input parameters (cohort students, projects, skills, locks, desired strategy, max alternatives). `AssignmentRun` is the output domain model representing the persisted execution record, containing the run's metadata, status, diagnostic telemetry, and generated alternative `Solution` instances.
3. **In the sequence diagram, why is `validate_inputs` called prior to solver execution?**
   - *Defense:* The system validates structural syntax and mathematical feasibility before attempting computationally heavy solver operations. If the cohort is provably infeasible (e.g. insufficient total capacity or contradictory fixed locks), execution terminates early with a clear diagnostic explanation rather than timing out in the ILP solver.
4. **Why is the Strategy Pattern advantageous over a monolithic solver function with `if/elif` statements?**
   - *Defense:* The Strategy Pattern adheres to the Open/Closed Principle (OCP). New allocation criteria (such as research group balancing or gender diversity) can be added as standalone strategy subclasses without altering existing solver orchestration or risking regression in validated algorithms.
