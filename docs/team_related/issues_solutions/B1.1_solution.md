# Issue B1.1 Solution — Skill-Fit Score and Gini Coefficient

## 1. Architectural Pattern Applied & Rationale
- **Headless Domain Service / Pure Analytical Calculator Pattern (`app/engine/metrics.py`):**
  - The skill-fit and Gini calculations reside strictly in Component B (`app/engine/`) as pure, stateless mathematical functions operating on domain entities (`models.Student`, `models.Project`) and primitive numeric lists.
  - Zero dependencies on Flask, HTTP context, or persistence layers are introduced, maintaining strict separation between Component A and Component B.

## 2. High-Level Logic & Data Flow Walkthrough
1. **`calculate_assignment_skill_fit(student, project)`:**
   - If `project.requirements` is empty, returns `(1.0, [])` immediately (100% fit, zero unmet skills).
   - Iterates over each `ProjectRequirement` in `project.requirements`:
     - Queries the student's proficiency via `student.get_skill_level(requirement.skill_id)` (defaults to `0` if missing).
     - Safeguards against division by zero (`if required_level <= 0: score = 1.0`).
     - Computes capped satisfaction ratio `min(student_level / required_level, 1.0)` so over-qualification in one skill cannot mask deficits in another.
     - Records `requirement.skill_id` in `unmet` whenever `student_level < required_level`.
   - Returns `(sum(scores) / len(scores), unmet)`.
2. **`calculate_gini(values)`:**
   - Validates that all input values are non-negative (`value < 0` raises `ValueError`).
   - Returns `0.0` for empty lists or all-zero totals (`total == 0`).
   - Computes pairwise absolute differences across all pairs $(i, j)$ and normalizes by $2 \cdot n \cdot \sum x_i$:
     $$G = \frac{\sum_{i=1}^{n} \sum_{j=1}^{n} |x_i - x_j|}{2 n \sum_{i=1}^{n} x_i}$$

## 5. Pedagogical Checkpoint ("Check Your Understanding")
1. **Why do we cap each individual requirement ratio at `1.0` (`min(student_level / required_level, 1.0)`) before averaging?**
   - So that a student with level 5 in Python (where level 2 is required) cannot compensate for having level 0 in a required SQL skill.
2. **Why does `calculate_gini` check `if total == 0: return 0.0`?**
   - If all values in a non-empty list are `0.0`, every participant has an identical outcome (complete equality, $G = 0.0$), and returning early prevents a division-by-zero error in $2 n \sum x_i$.
