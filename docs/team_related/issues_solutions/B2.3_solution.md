## 1. Architectural Pattern & Design Rationale
- **Pattern Applied:** Sequential Integer No-Good Cuts (Canonical Cut Constraints in Binary MILP).
- **Why Chosen:** To generate $K$ strictly distinct alternative solutions without returning duplicate allocations, each previously discovered assignment set $A^{(k)} = \{(s, p) : x^{(k)}_{s,p} = 1\}$ is excluded from subsequent solves by adding a linear cut constraint requiring at least one student to be assigned to a different project.
- **Component Scope:** `app/engine/strategies.py`, `tests/test_solvers.py`.

---

## 2. High-Level Logic & Data Flow Walkthrough
1. **Cut Formulation:** Given `excluded_solutions: list[list[tuple[str, str]]]`, for each prior solution $A^{(k)}$ containing valid $(s, p)$ pairs in the current cohort, `solve()` adds the constraint:
   $$\sum_{(s, p) \in A^{(k)}} x_{s,p} \le |S| - 1$$
2. **Mathematical Guarantee:** Since every feasible allocation assigns all $|S|$ students ($\sum_{s \in S} \sum_{p \in P} x_{s,p} = |S|$), any allocation identical to $A^{(k)}$ would sum to $|S|$, violating $\le |S| - 1$. Any allocation differing in at least one student's project has at most $|S| - 1$ overlapping pairs and remains feasible.
3. **Honest Exhaustion:** When all feasible allocations have been excluded (such as in a single-solution cohort where 1 student is matched to 1 project), the cut $\sum x_{s,p} \le 0$ contradicts $\sum x_{s,p} = 1$, causing HiGHS to report `infeasible` and `solve()` to return `("INFEASIBLE", [], None, diagnostics)` cleanly.

## 5. Check Your Understanding (Pedagogical Checkpoint)
1. *Why does the integer no-good cut use $|S| - 1$ on the right-hand side?*
   - **Defense:** Every valid assignment has exactly $|S|$ binary variables set to $1$ (one per student). Setting the upper bound of the sum over the previously chosen pairs to $|S| - 1$ forbids setting all $|S|$ of those same variables to $1$ simultaneously, while permitting any solution where at least one student moves to a different project.
2. *What happens if only 1 or 2 valid solutions exist in the feasible region, even though the user requested `max_alternatives = 3`?*
   - **Defense:** On the subsequent solve, the no-good cuts render the MILP infeasible. `solve()` returns `"INFEASIBLE"` with an empty assignment list, allowing `AssignmentEngine` to stop cleanly and return only the genuinely distinct solutions found (Edge Cases 14 & 15).
