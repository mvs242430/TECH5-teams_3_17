## 1. Architectural Pattern & Design Rationale
- **Pattern Applied:** Declarative Dependency Specification & Solver Plugin Architecture (`pyomo.environ.SolverFactory("appsi_highs")`).
- **Why Chosen:** Pyomo separates the algebraic MILP formulation (`ConcreteModel`, `Var`, `Constraint`, `Objective`) from the underlying numerical solver engine (`highspy` via Pyomo's APPSI interface `appsi_highs`). Pinning `pyomo>=6.7` and `highspy>=1.7` in `requirements.txt` ensures reproducible installation across macOS, Windows, and Linux without requiring external C++ solver binaries on the system PATH.
- **Component Scope:** `requirements.txt`.

---

## 2. High-Level Logic & Data Flow Walkthrough
1. `pip install -r requirements.txt` installs `pyomo` and `highspy` into `.venv`.
2. Component B invokes `pyo.SolverFactory("appsi_highs")`, which binds directly in-process to the HiGHS C++ library via `highspy`.

   - **Defense:** `highspy` provides pre-compiled Python wheels containing the HiGHS MILP solver library, so `appsi_highs` runs in-memory without requiring students or graders to install external solver executables on their operating system.
