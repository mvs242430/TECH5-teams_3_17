# Issue A2.1.1 Solution & Architectural Rationale

**Issue Title:** Issue A2.1.1 — Compare: solutions with different students  
**Branch:** `a2.1.1-compare-cohort`  
**Date:** 2026-10-30  
**Author / Lead:** Team A (A2 area)  

---

## 1. Architectural Pattern & Design Rationale
- **Pattern Applied:** MVC controller guard in `compare_solutions`, the same pattern as the existing unknown-ID check, plus the Repository Pattern for one new read and a clearer component contract.
- **Why Chosen:** The engine is right to refuse two solutions with different students, because Compare works student by student and a student who exists in only one solution has no before and after. Component B must stay headless, so it raises `ValueError` and the route turns that into a message for the user. SQL stays in `app/persistence/`. The `ValueError` is now in the contract docstring, so Component A knows to expect it.
- **Component Scope:** `app/visualization/` (route), `app/persistence/` (one new read), `app/contract/` and `app/engine/` (docstrings only).

---

## 2. High-Level Logic & Data Flow Walkthrough
1. **Why old solutions go empty:** `load_scenario` calls `clear_all_cohort_data`, which deletes all students. `assignments.student_id` has `ON DELETE CASCADE`, so the assignments of every older solution are deleted too, but the rows in `solutions` stay.
2. **Dropdowns:** `compare_solutions` asks `RunRepository.list_solution_ids_with_assignments()` which solutions still have assignments and offers only those. `list_runs` could not be used for this, because it loads metadata only and `sol.assignments` is always empty there.
3. **Emptied solution guard:** if either selected solution has no assignments (possible through an old link), the route shows a red message and redirects to `/compare`. This runs before the engine, because two empty solutions have equal student sets and would pass the engine's check, giving a blank result.
4. **Engine call:** `engine.compare_solutions` runs as before. If it raises `ValueError`, the route shows a red message and redirects to `/compare`.
5. **Normal case unchanged:** two solutions with the same students compare exactly as before, across one run or several.

## 5. Check Your Understanding (Pedagogical Checkpoint)
1. *Why does the engine keep raising `ValueError` instead of comparing the students both solutions share?*
   - Compare reports who moved and how averages changed. Averages over two different groups would mislead, so refusing is the honest result.
2. *Why is the empty check in the route when the engine already has a same-students check?*
   - Two empty solutions have equal student sets, so the engine's check passes and the page would be blank.
3. *Why could the dropdown not simply filter with `if sol.assignments`?*
   - `list_runs` fills only solution metadata, so that filter would hide every solution.
4. *How does this respect the component boundary?*
   - The engine still knows nothing about Flask. It raises a Python error named in the contract, and only the route produces the user message.
