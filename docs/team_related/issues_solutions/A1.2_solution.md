## Issue A1.2 (including A1.2.1 & A1.2.2) — Projects: Create, Edit, Delete with Required Skills

### 1. Architectural Pattern & Rationale
- **Blueprint / MVC Controller Pattern (`app/visualization/routes.py`):**
  - `create_project`, `edit_project_form`, `update_project`, and `delete_project` act as thin HTTP controllers that enforce role-based access control (`auth.can_edit_cohort_data()`), delegate form parsing and domain validation to the shared helper `_parse_and_validate_project_form`, and coordinate persistence through `ProjectRepository`.
- **Repository Pattern & 3NF Relational Persistence (`app/persistence/repositories.py`, `app/persistence/schema.sql`):**
  - `ProjectRepository.save` encapsulates the transactional `INSERT ... ON CONFLICT(id) DO UPDATE` on `projects` and synchronizes the child `project_requirements` rows (`DELETE` + `INSERT`).
  - `ProjectRepository.delete` removes the parent record from `projects`, relying on SQLite `PRAGMA foreign_keys = ON` and `ON DELETE CASCADE` to clean up dependent rows in `project_requirements`, `preferences`, `fixed_assignments`, and `assignments`.

### 2. High-Level Logic & Data Flow Walkthrough
1. **Create (`POST /projects/new`):**
   - Verifies Admin permission (`auth.can_edit_cohort_data()`).
   - Validates non-empty and non-duplicate `id` (`ProjectRepository.get_by_id`), retaining entered `form_data`, `req_levels`, and `req_mands` if validation fails (`A1.2.2`).
   - `_parse_and_validate_project_form` validates `title`, integer capacities (`0 <= min_capacity <= max_capacity` and `max_capacity >= 1`), skill levels (`0 <= level <= 5`), and ensures that if a skill's mandatory checkbox (`req_mand_<skillid>`) is ticked, its required minimum level is at least `1` (`A1.2.1`).
   - Builds `models.Project` with `models.ProjectRequirement` entries for all skills where `1 <= level <= 5` and persists via `ProjectRepository().save(project)`.
2. **Read & Render (`GET /projects`):**
   - `projects.html` renders each project's seat range (`{{ p.min_capacity }} – {{ p.max_capacity }} seats`) and iterates over `p.requirements` to display red `badge-danger` (`Must-have`) or blue `badge-primary` (`Nice-to-have`) skill badges.
3. **Edit & Update (`GET/POST /projects/<project_id>/edit`):**
   - `GET` builds `req_levels` and `req_mands` lookup dictionaries from `project.requirements` so `project_form.html` pre-fills both numeric levels and `checked` states on mandatory checkboxes.
   - `POST` re-validates via `_parse_and_validate_project_form` and updates both `projects` and `project_requirements` via `ProjectRepository().save(project)`.
4. **Delete (`POST /projects/<project_id>/delete`):**
   - Counts affected student preferences in `preferences`, deletes the project via `ProjectRepository().delete(project_id)`, and flashes an informational message reporting how many student preferences were cascaded.
